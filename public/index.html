헤드리스 리눅스 서버, Docker 컨테이너, CI/CD 자동화 파이프라인 전용 수동 쉘 스크립트 방식입니다. 아래 전체 스크립트를 참조하세요.
West CLI 터미널 수동 설치 스크립트 (복사하여 바로 실행 가능)
# 1. Python 가상환경 생성 및 활성화
python3 -m venv ~/ncs-env
source ~/ncs-env/bin/activate # (Windows: ~/ncs-env\Scripts\activate)

# 2. Zephyr 메타 도구 west 설치
pip install west

# 3. nRF Connect SDK 소스코드 초기화 및 다운로드
west init -m https://github.com/nrfconnect/sdk-nrf --mr v3.4.0 ~/ncs/v3.4.0
cd ~/ncs/v3.4.0
west update

# 4. Zephyr CMake 패키지 내보내기 & 의존성 라이브러리 설치
west zephyr-export
pip install -r zephyr/scripts/requirements.txt -r nrf/scripts/requirements.txt
💡
환경변수 필수 설정 안내: 수동 CLI 환경에서는 ZEPHYR_BASE=~/ncs/v3.4.0/zephyr 및 ZEPHYR_SDK_INSTALL_DIR=/opt/zephyr-sdk가 시스템 환경변수에 등록되어 있어야 빌드 툴체인(Arm GNU Toolchain)이 Zephyr 커널을 정상적으로 컴파일합니다.

2. 노르딕 개발키트(DK) 하드웨어 아키텍처, 포트 및 스위치 조작법

J2 vs J3 USB 포트 구분, SW8/SW9 스위치 조작, P22 전류 측정 헤더, 듀얼코어 SWD 라우팅
[노르딕 개발보드 하드웨어 인터페이스 배치도]

┌────────────────────────────────────────────────────────────┐
│ J2 포트 J-Link OB USB (메인 디버그/전원) │
│ ├── SEGGER J-Link 디버거 MCU 연결 (SWD 통신) │
│ ├── VCOM 가상 시리얼 포트 (115200bps 콘솔) │
│ └── 5V USB 입력 ➔ 3.0V VDD 레귤레이터 전원 인가 │
│ │
│ J3 포트 nRF Native USB (SoC 직접 연결) │
│ └── nRF5340 / nRF52840 자체 Full-Speed USB 컨트롤러 직접 테스트│
│ │
│ SW8 Main Power 전원 스위치 (ON / OFF) │
│ SW9 nRF ONLY 절체 스위치 (기본: DEFAULT) │
│ └── OFF 시: J-Link MCU 전원 차단 ➔ 극저전력 순수 SoC 전류 측정│
│ │
│ P22 Current Measurement 헤더 (2핀 점퍼) │
│ └── 점퍼 분리 후 PPK2(Power Profiler Kit II) 직렬 연결 │
│ │
│ SW5 IF BOOT/RESET 복구 스위치 │
│ └── 누른 상태로 USB 연결 시 J-Link 인터페이스 펌웨어 복구 모드│
└────────────────────────────────────────────────────────────┘
J2 (J-Link OB) vs J3 (nRF USB) 사용 규칙
• 평상시 실습 / 플래시 / 디버그: 항상 J2 포트만 PC에 연결합니다.
• J3 포트: SoC의 USB 주변장치(CDC ACM, HID 클래스)를 개발할 때 추가로 연결하는 보조 포트입니다. J3만 꽂으면 J-Link 프로그래머가 인식되지 않습니다!
P22 헤더와 PPK2(파워 프로파일러) 연동법
1. 보드 전원 스위치(SW8)를 끕니다.
2. P22에 꽂혀 있는 검은색 2핀 쇼트 점퍼를 제거합니다.
3. PPK2의 VOUT을 P22의 '+'핀에, VIN을 '-'핀에 직렬로 연결합니다.
4. SW9을 OFF(nRF ONLY)로 전환하면 온보드 J-Link MCU 누설전류 없이 순수 SoC 슬립 전류(1~2 uA)를 정밀 측정할 수 있습니다.
nRF5340 듀얼코어 타깃 식별
• App Core (128MHz): nrf5340dk/nrf5340/cpuapp (Matter 스택, BLE 호스트, 센서)
• Net Core (64MHz): nrf5340dk/nrf5340/cpunet (OpenThread / BLE 컨트롤러)
* 단일 J-Link SWD 버스에서 멀티 드롭 방식으로 두 코어를 개별 디버깅합니다.

3. 노르딕 4대 개발도구(Tooling Suite) 개념 및 실전 CLI 치트시트

nrfjprog, nrfutil, west, SEGGER J-Link RTT 및 Desktop GUI 앱 완벽 명령어 정리
A. nRF Command Line Tools (nrfjprog & nrfutil) 필수 도구
양산 팩토리 프로그래밍 및 로우레벨 제어를 담당하는 노르딕 공식 명령줄 툴입니다.
# 1. 칩 복구 (APPROTECT 읽기보호 해제 & 공장초기화)
nrfjprog --recover
nrfjprog --recover --coprocessor CP_NETWORK # nRF5340 Net Core

# 2. Hex 펌웨어 플래시 및 즉시 리셋 실행
nrfjprog --program build/zephyr/zephyr.hex --sectorerase --verify --reset

# 3. 물리 하드웨어 핀 리셋 발송
nrfjprog --pinreset

# 4. 최신 통합 nrfutil로 연결된 디바이스 조회
nrfutil device list
B. SEGGER J-Link & RTT (Zero-Overhead 콘솔) 초고속 로깅
UART 통신선 소모와 딜레이 없이, RAM 내부 링 버퍼를 SWD 버스로 직독직해하여 수십만 줄의 로그를 무간섭으로 출력합니다.
# 1. J-Link 대화형 SWD 콘솔 접속 (App Core 기준)
JLinkExe -device nRF5340_XXAA_APP -if SWD -speed 4000 -autoconnect 1

# 2. RTT 실시간 로그 스트리밍 클라이언트 수신
JLinkRTTClient

# 3. RTT 로그 파일 자동 저장 로거 실행
JLinkRTTLogger -device nRF5340_XXAA_APP -if SWD -speed 4000 rtt_output.log
C. West (Zephyr 메타 빌드 도구) 빌드 & 플래시
Git 서브모듈 통합 관리, CMake 빌드 오케스트레이션, 펌웨어 다운로드를 총괄합니다.
# 1. Matter 조명 샘플 타깃 빌드 (nRF5340 DK)

# 2. 클린 리빌드 (이전 빌드 캐시 완전 삭제 후 빌드)
west build -p always -b nrf5340dk/nrf5340/cpuapp nrf/samples/matter/light_bulb

# 3. 연결된 개발보드에 펌웨어 즉시 플래시
west flash

4. 실전 트러블슈팅 및 벽돌(Brick) 칩 복구 가이드

APPROTECT 잠김, Flash Overflow 메모리 부족, VDD 0.00V 전원 불량 해결 체크리스트
현상 1: J-Link 통신 불가 및 "Device is locked (APPROTECT)" 에러
원인: 최신 nRF SoC의 보안 기능인 APPROTECT(액세스 포트 보호)가 활성화되어 디버거의 메모리 읽기가 차단됨.
해결법: 아래 복구 명령을 터미널에서 순서대로 실행하여 보호를 강제 해제합니다:
nrfjprog --recover
nrfjprog --recover --coprocessor CP_NETWORK (nRF5340의 경우 필수)
현상 2: "FLASH overflowed by XXX bytes" 빌드 컴파일 에러
원인: Matter 프로토콜 스택과 상세 로깅(ASSERT/LOG_DBG)으로 플래시 1MB 용량을 초과함.
해결법:
• prj.conf에 CONFIG_SIZE_OPTIMIZATIONS=y 추가
• 디버그 로그 레벨을 낮춤: CONFIG_MATTER_LOG_LEVEL_INF=y
• 릴리즈 전용 설정 파일 사용: west build -b ... -- -DCONF_FILE=prj_release.conf
현상 3: S/N은 보이나 VDD = 0.00V (전원 없음) 표출 및 플래시 실패
체크리스트:
1. 보드 우측 하단 SW8 전원 스위치가 'ON' 위치인지 확인.
2. 케이블이 충전 전용이 아닌 데이터 전송 지원 USB-C 케이블인지 확인.
3. P22 전류 측정 핀에 2핀 점퍼가 꽂혀 있는지 확인 (점퍼 누락 시 SoC에 전원 미공급).
현상 4: 스마트홈 앱 페어링 시 "기기를 찾을 수 없음" 타임아웃
체크리스트:
1. 보드 부팅 후 15분 경과 시 BLE 커미셔닝 윈도우가 닫힙니다 ➔ Button 2를 눌러 재시작.
2. Discriminator (기본값 3840)와 Passcode (20202021)가 QR 코드와 일치하는지 확인.
3. Thread Border Router(Google Nest Hub, Apple HomePod 등)가 동일 Wi-Fi에 켜져 있는지 확인.
